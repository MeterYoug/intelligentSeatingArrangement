# 慧排座设计系统：静青教务

版本：V1.0  
适用端：PC Web 管理后台  
适用技术：Vue3、Vite、Element Plus、若依 Vue3

## 1. 设计结论

慧排座采用「静青教务」设计风格：以温和青绿色建立教育属性，以清晰、可信、可解释为核心，不做幼儿化校园风，也不继续沿用缺少产品识别度的若依默认蓝色后台。

整体观感应像一张整理有序的教师办公桌：温和但不幼稚，专业但不冷漠，数据密集但不拥挤，有智能能力但不制造“AI 炫技感”。

## 2. 品牌三问

### 2.1 产品身份

面向班主任和教务人员的智能排座工作台。

### 2.2 核心记忆

排座过程清楚，结果能够解释，调整可以撤回。

### 2.3 核心行动

导入学生 → 配置规则 → 生成方案 → 人工微调 → 检查确认 → 导出座位表。

所有页面内容和操作层级都应服务这条主流程。

## 3. 设计原则

1. 任务优先：页面首先告诉老师“现在能做什么”。
2. 结果可解释：不能只给评分，还要说明哪些规则满足、哪些没有满足。
3. 操作可回退：拖拽、清空、换座等操作必须支持撤销或恢复。
4. 熟悉感优先：继续使用 Element Plus 的成熟交互，不重新发明组件。
5. 长时间使用友好：低刺激配色、足够字号，减少大面积高饱和颜色。
6. 状态不只靠颜色：颜色必须配合文字、图标或边框形态。
7. 数据关怀：学生信息展示克制，不用装饰性视觉强化敏感属性。

## 4. 颜色系统

### 4.1 基础颜色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 品牌主色 | `#2C9486` | 主按钮、选中状态、导航高亮 |
| 主色悬停 | `#6BB4AA` | 按钮悬停、强调状态 |
| 主色浅底 | `#EAF4F3` | 选中行、提示区、轻量标签 |
| 页面背景 | `#F5F7F6` | 后台整体背景 |
| 内容表面 | `#FFFFFF` | 表格、表单、座位区域 |
| 主文字 | `#1F2937` | 标题、姓名、关键数据 |
| 次要文字 | `#667085` | 说明、时间、辅助字段 |
| 弱文字 | `#98A2B3` | 占位符、禁用信息 |
| 边框 | `#DDE5E2` | 卡片、输入框、表格分割 |

### 4.2 语义颜色

| 状态 | 色值 | 用途 |
| --- | --- | --- |
| 成功 | `#2F7D5B` | 保存成功、规则满足、已确认 |
| 警告 | `#B7791F` | 已锁定、待处理、部分满足 |
| 错误 | `#C2413B` | 规则冲突、危险操作、校验失败 |
| 信息 | `#356AA0` | 普通说明、处理进度 |

品牌主色只负责品牌和交互状态。成功、警告、错误继续使用语义色，不能为了统一而把所有状态都变成青绿色。

### 4.3 禁止使用

- 紫色渐变和霓虹色。
- 大面积蓝绿渐变。
- 用粉色代表女生、蓝色代表男生的强性别配色。
- 装饰性光斑、玻璃拟态、3D 元素和卡片套卡片。

## 5. 字体与字号

### 5.1 字体栈

```css
font-family: "HarmonyOS Sans SC", "Microsoft YaHei", system-ui, sans-serif;
```

不依赖必须联网加载的字体，保证学校 Windows 电脑可稳定显示。

### 5.2 字号层级

| 层级 | 尺寸 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | `20px / 28px` | 600 | 学生管理、座位方案 |
| 区块标题 | `16px / 24px` | 600 | 基础信息、规则检查 |
| 正文与表格 | `14px / 22px` | 400 | 主要后台内容 |
| 关键姓名 | `15–16px` | 600 | 座位卡片学生姓名 |
| 辅助信息 | `12px / 18px` | 400 | 学号、座位编号、提示 |

老师高频操作区域不得使用低对比度的 `12px` 灰字作为正文。

## 6. 间距、尺寸与层级

### 6.1 间距系统

所有间距优先从以下数值中选取：

```text
4 / 8 / 12 / 16 / 24 / 32
```

### 6.2 组件尺寸

- 输入框和普通按钮高度：`36px`。
- 主要操作按钮高度：`40px`。
- 表格默认行高：`48px`。
- 紧凑表格行高：`40px`。
- 页面内容边距：`20–24px`。
- 左侧导航展开宽度：`220px`。

### 6.3 圆角与阴影

- 卡片圆角：`8px`。
- 输入框、按钮圆角：`6px`。
- 标签圆角：`4px`。
- 优先使用 `1px` 边框区分层级。
- 阴影只用于弹窗、抽屉和浮层，不给每张卡片加阴影。

## 7. 后台整体结构

### 7.1 导航

- 左侧导航宽度 `220px`，支持收起。
- 默认侧边栏为浅色主题：白底（#FFFFFF）+ 主色文字（#2C9486），激活项用淡青浅底（#EAF4F3）；不再使用整块墨绿深色背景。
- 菜单使用教师语言：班级管理、学生管理、成绩管理、教室布局、排座规则、座位方案。
- 系统管理等低频能力与排座业务导航明确分组。

### 7.2 页面标题区

每个页面只保留：页面名称、一句任务说明和一个主要操作。

示例：

```text
学生管理
维护学生资料和排座相关属性。
［导入学生］
```

不使用营销式 Hero、大号口号或无业务意义的欢迎语。

## 8. 核心页面模板

### 8.1 首页工作台

首页不做数字大屏，使用老师的任务入口：

1. 当前班级和当前方案。
2. “开始一次排座”主入口。
3. 数据准备检查：学生、教室、规则、成绩是否齐全。
4. 最近座位方案。
5. 待处理问题：未安排学生、规则冲突、未确认方案。

统计数字只保留能指导下一步行动的数据。

### 8.2 列表管理页

统一结构：

```text
页面标题
筛选区
主要操作区
数据表格
分页
```

规则：

- 筛选默认不超过一行，更多条件折叠。
- 主要操作放左侧，批量操作紧随已选数量。
- 操作列固定在右侧。
- 状态使用文字标签，不能只显示颜色圆点。
- 空状态直接给出“新增班级”“导入学生”等下一步入口。

### 8.3 表单与弹窗

- 简单新增、编辑使用弹窗或抽屉。
- 复杂规则配置使用独立页面。
- 表单标签宽度统一，单位紧跟输入值。
- 专业术语必须带业务解释。
- 不向普通老师暴露 JSON、算法参数名或数据库字段。
- 提交失败直接定位具体字段，并给出修正方式。

## 9. 排座详情页

### 9.1 页面结构

采用两栏结构：

```text
方案状态与主要操作
规则摘要、评分和异常概览
座位图主区域 ｜ 右侧检查面板
底部未保存操作条
```

尺寸建议：

- 座位图使用剩余自适应宽度。
- 右侧检查面板宽度 `300–320px`。
- 规则配置通过顶部摘要或抽屉查看，不常驻第三栏。

在 1366px 屏幕扣除侧栏后，三栏结构会挤压座位图，因此不采用“规则栏＋座位图＋问题栏”的固定三栏布局。

右侧检查面板使用以下标签页：

- 未安排学生。
- 规则检查。
- 调整记录。

### 9.2 座位卡片

信息优先级：

1. 学生姓名。
2. 座位编号。
3. 最多两个关键规则标签。
4. 锁定或冲突标记。

状态规范：

| 状态 | 表现 |
| --- | --- |
| 普通已安排 | 白底、青色边框 |
| 空座 | 白底、虚线边框并显示“空座” |
| 已锁定 | 琥珀色顶部标记、锁图标和“已锁定” |
| 规则冲突 | 红色边框、警告图标和冲突数量 |
| 过道 | 浅灰底并明确显示“过道” |
| 不可用 | 禁用图标和“不可用” |

不能仅依赖红、绿、黄区分状态。

### 9.3 拖拽调整

- 拖拽开始时显示原座位和目标座位。
- 放置前显示换座预览。
- 每次调整后立即刷新规则检查。
- 页面底部出现固定操作条：“有 3 项调整未保存｜撤销｜恢复｜保存调整”。
- 离开页面前提示未保存内容。
- 已确认方案禁止直接拖拽，只提供“复制为新草稿”。

## 10. 动效与反馈

- 普通反馈时长：`120–180ms`。
- 抽屉和弹窗：`180–240ms`。
- 不做页面整体入场动画。
- 拖拽可以有轻微缩放和阴影，但不能弹跳。
- 排座生成超过 1 秒时展示步骤：“检查数据 → 应用规则 → 生成方案 → 校验结果”。
- 失败提示必须说明原因和处理入口，不能只写“生成失败”。

## 11. 文案风格

采用老师熟悉的业务语言：

- “未安排 2 名学生”，不写“存在异常数据”。
- “可用座位不足，还需要 3 个座位”，不写“参数校验失败”。
- “该方案已经确认，请复制为新草稿后调整”，不写“当前状态不可编辑”。
- “系统已尽量满足 8 条规则，其中 2 条未完全满足”，不承诺“最优排座”。

按钮统一使用动作词：

```text
新增、导入、生成方案、保存调整、确认方案、复制草稿、导出座位表
```

## 12. 实施边界

### 12.1 保留

- Vue3、Vite、Element Plus。
- 若依权限、菜单、表格、表单和弹窗机制。
- 当前慧排座 Logo 和业务功能结构。

### 12.2 重点调整

- 全局颜色和设计 token。
- 导航、页面标题、筛选区和表格密度。
- 首页工作台。
- 座位方案详情页。
- 空状态、错误状态和未保存反馈。

### 12.3 不做

- 营销型首页。
- 暗色主题。
- 装饰性插画体系。
- 复杂动效。
- 全面替换 Element Plus。
- 为追求美观而隐藏关键业务字段。

## 13. 分阶段实施顺序

1. 建立全局设计 token，仅调整颜色、字体、间距、圆角和基础状态。
2. 先改首页工作台，验证品牌方向和页面骨架。
3. 再改学生管理，验证列表、筛选、表格和弹窗规范。
4. 最后改排座详情，验证座位状态、拖拽反馈和规则解释。
5. 三类页面验收通过后，再统一其余业务页面。

每阶段先完成一个代表页面并目视验收，不一次性重做全站。

## 14. 验收标准

1. 新老师在 3 分钟内知道如何开始第一次排座。
2. 老师不看说明文档也能完成生成、调整、确认和导出。
3. `1366×768` 下主要按钮、表格操作列和座位图不溢出。
4. 页面缩放到 `125%` 后仍可完成核心流程。
5. 所有状态都有颜色之外的文字或图标表达。
6. 拖拽调整能够撤销，并明确提示是否已保存。
7. 每条未满足规则都有原因和建议处理方式。
8. 连续使用 30 分钟没有明显的高亮色和动画干扰。
9. 打印视图只保留班级、方案、讲台、座位图和必要说明。
10. 全站不存在若依默认蓝色、项目自定义蓝色和新青色混用。

## 16. 设计依据

本设计系统吸收以下方法：

- 先明确身份、记忆和行动，再决定视觉表现。
- 设计描述必须转换为色值、字号、间距等可执行数值。
- 锁定现有技术和组件边界，避免为了换风格重写系统。
- 为每类页面设置可观察的验收尺子。
- 先搭骨架和代表页面，逐阶段目视验收后再扩展。
