## 1. 演示数据建议

当前本地演示建议保留一套最小但完整的业务链路数据：

- 1 个班级。
- 1 套教室布局。
- 1 套启用中的座位方案。
- 至少 1 次生成历史和 1 次人工微调历史。
- 至少 1 次 Excel、PNG、PDF 导出记录。

建议展示顺序：

1. 班级管理。
2. 学生管理。
3. 教室布局。
4. 排座规则。
5. 座位方案生成与详情。
6. 历史方案对比。
7. 导出 Excel、PNG、PDF。

建议保留的演示侧重点：

- 方案差异要能看懂原位与现位变化。
- 导出结果要带当前视角。
- 批量选择、锁定、撤销、重做、保存要能闭环。
- 评分明细要尽量用老师能直接理解的语言。

## 2. 本地部署说明

### 2.1 运行前提

- 后端：`RuoYi-Vue-springboot3`
- 前端：`RuoYi-Vue3-master`
- 本地端口：
  - 后端：`http://localhost:8310`
  - 前端：`http://localhost:8222`
  - 验证码：`http://localhost:8310/captchaImage`
  - 前端代理：`http://localhost:8222/dev-api/captchaImage`

### 2.2 启动顺序

1. 启动后端。
2. 确认后端接口可访问。
3. 启动前端。
4. 打开前端页面并登录。

### 2.3 常用命令

后端编译：

```bash
cd RuoYi-Vue-springboot3
mvn -DskipTests compile
```

前端生产构建：

```bash
cd RuoYi-Vue3-master
npm run build:prod
```

前端开发启动：

```bash
cd RuoYi-Vue3-master
npm run dev
```

### 2.4 SSH 推送

当前仓库远程使用 SSH：

```text
git@github.com:MeterYoug/intelligentSeatingArrangement.git
```

本机已配置 GitHub SSH 走 443 端口，适用于 22 端口受限的环境。

## 3. 稳定回归清单

### 3.1 基础可用性

- 登录页可打开。
- 首页可打开。
- 智能排座菜单可见。
- 班级、学生、教室布局、排座规则、座位方案页面可访问。

### 3.2 核心业务闭环

- 新增或编辑班级后，年级、学期和班级科目回显正常。
- 学生导入可下载模板、上传 Excel，并支持按学号更新。
- 教室布局可保存，过道和不可用座位正确显示。
- 规则启用后参与方案生成。
- 一键生成可创建座位方案。
- 详情页可正常展示座位表、未安排学生和评分明细。

### 3.3 高频交互

- 撤销。
- 重做。
- 批量选择。
- 批量锁定。
- 批量解锁。
- 空座清空。
- 未安排学生回填。
- 保存调整。
- 确认启用。

### 3.4 历史方案

- 可查看同班历史方案。
- 可对比方案差异。
- 可复制历史方案。
- 可恢复归档方案。

### 3.5 导出

- Excel 导出。
- PNG 导出。
- PDF 导出。
- 导出文件名需包含方案名和当前视角。

### 3.6 回归验证建议

建议优先验证下面这些场景：

1. 生成后直接导出。
2. 拖拽后保存再刷新。
3. 批量锁定后撤销再重做。
4. 切换教师视角和学生视角。
5. 方案差异选择并回填。

### 3.7 最低验收标准

- 后端 `mvn -DskipTests compile` 通过。
- 前端 `npm run build:prod` 通过。
- 真实浏览器能完成登录、生成、微调、保存、确认和导出闭环。
