# 阶段 9 P1：座位方案详情页高频交互收口设计

**背景**

当前 `RuoYi-Vue3-master/src/views/seating/plan/detail.vue` 已具备撤销／重做、批量锁定／解锁、保存调整、确认方案、导出等能力，但按钮禁用条件和失败提示仍然分散在各个事件函数中，存在三类问题：

1. 同类操作的禁用条件不统一。
2. 并发状态下（加载、保存、确认）存在重复点击或提示不一致风险。
3. 页面模板和脚本中的状态判断散落，后续继续增强时容易回归。

**目标**

本轮只收口一个 P1 子项目：统一座位方案详情页高频操作的可点击状态、阻塞原因和用户提示，不扩展新业务能力，不改后端接口。

**范围内**

- 撤销。
- 重做。
- 批量选择开关。
- 批量锁定／解锁。
- 保存调整。
- 确认方案。
- Excel／图片／PDF 导出。

**范围外**

- 模板复用。
- 新学期复制。
- 排座算法调整。
- 新的后端接口。
- 复杂 UI 重构。

**方案选择**

采用“抽离纯状态判断模块 + 页面接入”的方案。

原因：

- 纯函数可以独立测试，不依赖 Vue 运行时。
- 能在不大改页面结构的前提下统一禁用条件和阻塞提示。
- 更符合当前项目没有现成前端测试框架、但可以用 Node 内置测试先覆盖纯逻辑的现状。

**设计**

1. 新增一个纯逻辑模块，负责根据 `loading`、`saving`、`confirming`、`dirty`、`undoStack`、`redoStack`、`selectedSeatIds`、`seatRows`、`planStatus` 生成统一的操作状态。
2. 同时提供阻塞提示文案函数，页面内所有高频操作都先走同一套 guard。
3. 页面模板改为消费统一状态，不再把禁用逻辑散写在按钮上。
4. 页面事件函数在真正执行前统一校验，并使用一致的 warning 文案。

**验收标准**

- 页面加载、保存、确认中的任一繁忙状态下，相关高频按钮不会重复触发。
- 没有未保存更改时，“保存调整”不可执行，且提示一致。
- 有未保存更改时，“确认方案”和三类导出不可执行，且提示一致。
- 未选择座位时，批量锁定／解锁不可执行，且提示一致。
- 撤销／重做无历史时不可执行，且提示一致。
- 本轮不改变既有业务接口和页面核心布局。
